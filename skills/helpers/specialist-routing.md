# Specialist skill routing

Consult `specialist_skills` in the installed `.codex/delivery-framework/subskills.json` for matching activation and role, including work the master agent owns. Read a candidate only when its extra depth benefits the assignment. Check the runtime skill catalog: an inventory entry does not prove installation or active version. If absent, use its listed framework fallback and report a material capability gap. Do not install skills automatically. User-invoked skills and higher-priority instructions prevail; resolve conflicting guidance in their favor. Existing local helpers remain conditional.

For delegated work, provide matching candidates and fallbacks in the assignment; the subagent checks availability in its own runtime and loads selected skills. Catalog entries are not exhaustive: explicitly requested skills remain authoritative.

Choose by the actual task and artifact, not overlapping keywords. Load a broad router when needed to select a workflow, then only the applicable specialist and references; do not load every candidate in a domain. Combine skills when each contributes a distinct needed capability. Respect external plugins' own routing and runtime instructions.
