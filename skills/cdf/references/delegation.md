# Bounded delegation and operator policy

The root owns user communication, decisions, integration and completion. Work directly by default. Delegate an independent research branch, disjoint implementation or meaningful independent review only when the benefit exceeds coordination and repeated-context costs. A role is a responsibility, not a requirement to spawn.

Settle shared contracts first. Assign objective, baseline and current diff, scope/write ownership, accepted decisions with sources, dependencies, observable acceptance, permissions, raw evidence needed and known gaps. For outcome work include the original complaint, failed hypotheses and preserved behavior. Workers are not alone; they must accommodate others' changes and never revert them. Workers do not spawn children. Reviewers remain read-only. The root inspects actual changes and evidence before integrating.

Default to at most two simultaneous workers; obey a smaller operator budget and count existing workers. Exceed two only with explicit authorization. Missing mandatory independent review blocks reviewed readiness, not legitimate preparation.

Read an advisory model policy only when the operator selects its path. Its profile, worker budget, medium-risk review preference and fallback rules guide proposals; examples are not active configuration. Distinguish available, requested and observed model/effort. Check actual runtime capabilities before requesting an override. An explicit model requirement forbids substitution; disclose inherited fallback only when allowed. Unknown or unsupported policy values cannot authorize action. Never change the root session or global configuration via a policy file. The optional model-calibration skill owns detailed calibration on explicit request.

Absent a policy, use current runtime settings, direct work and risk-based review. Check optional catalog candidates for actual discovery, compatibility and provenance; never install automatically. Missing optional helpers use local methods. Catalog entries, TOML templates and instruction length prove neither runtime activation nor savings.
