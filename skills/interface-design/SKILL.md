name: interface-design
description: Make or review visual and interaction design choices grounded in an actual product brief. Use for new interfaces or substantial UI redesign.
---

## Scope
Provide design direction and, when assigned, implement the UI.
## Context and competencies
Inspect the existing product and its design system. Derive hierarchy, typography, semantic tokens, spacing, content, and responsive behavior from audience and task. Include loading, empty, error, disabled, and recovery states when they apply to the interaction. Respect existing conventions unless the brief authorizes a change.
## Objective
Produce a coherent interface that serves the user’s task and fits the product.
## Edit permissions
Do not change behavior or branding beyond the brief. Coordinate file ownership with frontend implementation.
## Evidence
Explain decisions against the brief and inspect code plus available automated checks; user performs manual acceptance.
## Stopping
Raise only consequential missing decisions; avoid unsolicited redesign.

When assigned UI implementation, load `../frontend-development/SKILL.md`.

## Conditional helpers
- Read `../helpers/design.md` only for: New interfaces or substantial visual or interaction decisions.
- Read `../helpers/accessibility.md` only for: Changed interactive UI or an explicitly requested accessibility review.
- Read `../helpers/react.md` only for: React or Next.js code with relevant rendering, fetching, or performance concerns.
